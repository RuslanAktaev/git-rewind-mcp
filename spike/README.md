# Эксперимент: смысловой поиск по merge request'ам

Проверка идеи «делали мы уже такое?» на живых данных. Не часть MCP-сервера —
одноразовые скрипты, чтобы понять, работает ли подход вообще.

## Что нужно

- Токен GitLab с правом `read_api` в `~/.gitlab-token` (одна строка, без кавычек).
- Ollama с моделью эмбеддингов:
  ```
  brew install ollama && ollama serve
  ollama pull bge-m3
  ```
  Модель задаётся переменной `EMBED_MODEL`, по умолчанию `bge-m3`.

## Как запускать

```bash
# 1a. один проект (1834 = docky-react-native, 2269 MR, ~35 секунд)
python3 spike/1-fetch-mrs.py 1834 /tmp/docky.jsonl

# 1b. или все проекты, где состоит пользователь (22 365 MR, ~390 секунд)
python3 spike/4-fetch-all.py /tmp/all-mrs.jsonl

# 2. посчитать векторы (22 365 записей — ~400 секунд, файл 211 МБ)
python3 spike/2-embed.py /tmp/all-mrs.jsonl /tmp/all.vec.jsonl

# 3. искать (запросы аргументами, ПО-АНГЛИЙСКИ)
python3 spike/3-search.py /tmp/all.vec.jsonl "two-factor authentication OTP"

# 4. проверить качество на размеченных запросах
python3 spike/5-eval.py /tmp/all.vec.jsonl
```

Данные наружу не кладём: это код заказчика. Файлы `.jsonl` держать вне репозитория.

## Что делает каждый скрипт

**1-fetch-mrs.py** — один проект, 30 страниц по 100 MR в 8 потоков. Годится
для быстрой пробы; на проекте больше 3000 MR молча обрежет.

**4-fetch-all.py** — все проекты, где состоит пользователь. Идёт по страницам,
пока GitLab отдаёт полные, повторяет при обрывах и таймаутах, пропускает 4xx.
На 142 проектах: 22 365 MR из 106, 36 проектов без единого MR (два из них —
403, доступа к их MR у токена нет).

**2-embed.py** — чистит заголовок (срезает префикс задачи `86bwzyu7q:`, ссылки на
ClickUp, упоминания `@user`), склеивает с описанием и шлёт по одному запросу на запись:

```
POST http://127.0.0.1:11434/api/embeddings
{"model":"bge-m3","prompt":"Connected add absence period modal to api"}
→ {"embedding":[-0.23218, -0.87531, ... 1024 числа]}
```

**3-search.py** — считает вектор запроса, перемножает его с каждой записью,
сортирует, печатает пятёрку. Рядом показывает отрыв первого и пятого результата
от общего фона в сигмах — но вердикт «нашли / не нашли» не выносит, см. ниже.

**5-eval.py** — прогон на размеченных запросах: для каждого заранее известно
регуляркой, что должно найтись. Показывает, попал ли эталон в пятёрку.

## Результат

Поиск работает: на 7 размеченных запросах эталон попал в пятёрку 7 раз из 7.

Три вывода, которые дались только на полной базе и опровергли выводы,
сделанные на одном проекте.

**1. Русский запрос заметно слабее английского.** `bge-m3` многоязычная, но база
целиком английская — кириллица нашлась в 2,3% заголовков, и та оказалась
опечатками раскладки. На 2269 записях разницы было не видно, на 22 365 видно:

| запрос | верхний результат | попал? |
|---|---|---|
| `two-factor authentication OTP` | 0.762 Implement OTP-based 2FA verification flow | да |
| `двухфакторная аутентификация по смс` | 0.660 Email verification | нет, а 2FA в базе есть — 27 MR |

**2. Порог работает по самой оценке близости — но только по ней.** На 21
размеченном запросе (13 существующих тем, 8 отсутствующих) самая слабая находка
дала 0.685, самый сильный промах 0.667. Граница около 0.675, ни одного
пересечения, запас 0.018.

А вот отрыв верхнего результата от фона, который проверялся как замена порогу
для русских запросов, не годится. Он растёт вместе с базой (находка: 4.27 на
тысяче записей → 8.03 на 22 365; промах: 2.94 → 5.17) и вдобавок работает
наоборот:

| запрос | отрыв первого | отрыв пятого | в базе |
|---|---|---|---|
| `nuclear reactor control panel` | **7.7σ** | 5.0σ | нет — вытянул одинокий `admin panel` |
| `google maps on screen` | 5.5σ | 4.9σ | есть, плотная группа из 5 |

Одинокий случайный выброс даёт больший отрыв, чем настоящая тема: плотная группа
похожих результатов сама поднимает фон. По первому результату диапазоны
пересекаются (5.48 у находки против 5.82 у промаха), по пятому тоже.

**3. Составные запросы дают ложную тревогу.** «pay with cryptocurrency bitcoin»
уверенно возвращает платёжные MR: «pay» совпало с тысячей записей, а различающее
«cryptocurrency» не учитывается никак. Криптоплатежей в базе нет. Лечится
гибридом — вектор плюс полнотекстовый поиск по словам запроса.

Отсюда решение в спеке: ниже 0.675 сервер отвечает «похожего не нашлось», выше —
отдаёт пятёрку, а «то самое или мимо» решает агент, читая заголовки.
