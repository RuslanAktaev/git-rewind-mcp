# Эксперимент: смысловой поиск по merge request'ам

Проверка идеи «делали мы уже такое?» на живых данных. Не часть MCP-сервера —
одноразовые скрипты, чтобы понять, работает ли подход вообще.

## Что нужно

- Токен GitLab с правом `read_api` в `~/.gitlab-token` (одна строка, без кавычек).
- Ollama с моделью эмбеддингов:
  ```
  brew install ollama && ollama serve
  ollama pull nomic-embed-text
  ```

## Как запускать

```bash
# 1. выкачать MR проекта (1834 = docky-react-native, 2269 MR, ~40 секунд)
python3 spike/1-fetch-mrs.py 1834 /tmp/docky.jsonl

# 2. посчитать векторы (~28 секунд на 2269 записей)
python3 spike/2-embed.py /tmp/docky.jsonl /tmp/docky.vec.jsonl

# 3. искать (запросы — аргументами, ПО-АНГЛИЙСКИ)
python3 spike/3-search.py /tmp/docky.vec.jsonl "chat between users" "profile photo upload"
```

Данные наружу не кладём: это код заказчика. Файлы `.jsonl` держать вне репозитория.

## Что делает каждый скрипт

**1-fetch-mrs.py** — 30 запросов к `/api/v4/projects/:id/merge_requests` по 100 штук
за раз, в 8 потоков. Сохраняет номер, заголовок, описание, дату и ссылку.

**2-embed.py** — чистит заголовок (срезает префикс задачи `86bwzyu7q:`, ссылки на
ClickUp, упоминания `@user`), склеивает с описанием и шлёт по одному запросу на запись:

```
POST http://127.0.0.1:11434/api/embeddings
{"model":"nomic-embed-text","prompt":"Connected add absence period modal to api"}
→ {"embedding":[-0.23218, -0.87531, ... 768 чисел]}
```

Складывает текст и числа в файл. 2269 записей — 16 МБ.

**3-search.py** — шлёт такой же запрос для вопроса, получает 768 чисел, перемножает их
попарно с числами каждой из 2269 записей и складывает. Сортирует по этому числу,
печатает пятёрку. Обращений к модели — одно на вопрос, дальше только арифметика.

## Результат

Работает — но только на английских запросах.

| запрос | лучшее совпадение | оценка |
|---|---|---|
| `chat between users, messaging` | Chat Messages | 0.82 |
| `profile photo upload` | Profile avatar upload issue | 0.83 |
| `biometric login face id` | (в проекте такого нет) | 0.63 |
| `чат между пользователями` | мусор — переводы, настройки языка | 0.52 |

Два вывода:

1. **Оценка отделяет находку от промаха.** 0.82 когда есть, 0.63 когда нет. Значит,
   можно честно отвечать «не нашёл», а не выдавать пять случайных MR.
2. **Русский не работает.** `nomic-embed-text` понимает только английский. Лечится либо
   многоязычной моделью (`bge-m3`), либо тем, что запрос пишет агент — а он может
   и по-английски.
